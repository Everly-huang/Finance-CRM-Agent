# Word 文档转 Markdown（docx → md）

将 `.docx` 转换为同目录同名 `.md` 文件，要求信息结构完整、格式规范、可读性强（无损转换）。

## 执行流程

### 第 1 步：提取 docx 内部 XML

`.docx` 本质是 ZIP 压缩包，核心内容在 `word/document.xml`。在 Git Bash 中：

```bash
mkdir -p /tmp/docx_extract && cd /tmp/docx_extract
unzip -o "<docx绝对路径>" > /dev/null
ls word/media 2>/dev/null   # 确认有无嵌入图片
```

### 第 2 步：运行结构提取脚本

用本技能自带的 `scripts/extract_docx.js`（Node.js）解析 `document.xml` / `numbering.xml` / `rels`，生成可读的结构清单：

```bash
# 注意：Windows 下 Node 不识别 /tmp，先用 cygpath 转 Windows 路径
WORD_DIR=$(cygpath -w /tmp/docx_extract/word)
node "<skill目录>/scripts/extract_docx.js" "$WORD_DIR" "$(cygpath -w /tmp/docx_extract/dump.txt)"
```

脚本输出 `dump.txt`，每块一行头 + 内容：段落（字号 sz、是否全加粗 bold、编号 numId/ilvl/outline/格式 fmt、是否含图）、表格（行列数、每行单元格文本、跨列 span）。

### 第 3 步：通读结构清单，确定映射关系

- **标题层级**：以 `outline`（大纲级别）和字号 `sz`（单位 pt，`w:sz` 半磅值÷2）综合判断。
  经验值：sz≈24 → `#` 文档标题；sz≈16 + outline=1 → `##` 一级章节；sz≈15 → `###` 小节；sz≈14 → `####` 子小节。
  注意 WPS 生成的文档常无 pStyle，且 outline 标注可能不一致——以字号+同级文本规律（如 "5.1 完整架构" 与 "2.1 业务背景" 同级）为准，**禁止跳级**。
- **列表类型**：`fmt=decimal` → 有序列表 `1.`；`fmt=bullet` → 无序列表 `-`。
  `numId=0`、字面符号（`•`、`·`、`├─`、`└─`、`│`）或同一视觉列表内 numId 不连续（WPS 每项独立编号实例）→ 按视觉层级合并为一个列表。
- **目录树/文件树**（含 `├──` `└──` `│` 字符且为路径文本）→ ` ```text ` 代码块，原样保留缩进与注释。
- **表格**：无跨列 → 标准 Markdown 表格；有 `gridSpan`/`vMerge` → 拆分简单表格，无法拆分则用 HTML `<table>`。
- **图片**：查 `word/media` 与 dump 中 `IMG refs`，按规则转占位；无图片则不添加。
- **空段落**（无文本无图）直接跳过（dump 中已过滤）。

### 第 4 步：按输出规范编写 Markdown（见下节）

用 Write 工具输出到与 docx 同目录、同名的 `.md` 文件。

### 第 5 步：校验

```bash
grep -c '^#'  目标文件.md   # 标题总数
grep -c '^|'  目标文件.md   # 表格行总数
```

对照 dump 核对：章节数、表格张数、列表项数是否一致，抽查原文与转换后文本逐字一致（含引号曲直、空格）。

## 输出规范（转换规则）

### 1. 表格
- 全部转为 Markdown 标准表格（`|` 分隔 + `|---|---|` 表头分隔行），保留表头；原文无表头则据内容补合理表头。
- 单元格内换行用 `<br>`，禁止破坏表格结构。
- 表格后紧跟一个空行，再衔接正文。

### 2. 列表
- 项目符号 → `-`；编号 → `1. 2. 3.`。
- **严格保留层级**：一级顶格，二级缩进 2 空格，三级缩进 4 空格。
- 列表项含多段文字时，次级段落缩进与列表项内容对齐（有序列表下续段缩进 3 空格与 `1. ` 对齐）。
- 列表项内嵌套表格/代码块保持完整并整体对齐到列表层级。
- 禁止把列表扁平化为纯文本。

### 3. 架构图/流程图 → Mermaid
- 原文包含图形时转换为 Mermaid 块：
  - 流程图 → `graph TD`/`graph LR`；架构图 → `graph TB`；时序图 → `sequenceDiagram`；甘特图 → `gantt`。
- 保留所有节点文本、判断条件、连线关系，不遗漏任何模块。
- 原文无图形、但文字明确描述了架构（如"四层架构"）时，可依据文字补充 Mermaid 图，并在代码块上方加注释说明：
  `<!-- 注：原文未含图形，下图为依据本节文字描述绘制的架构示意 -->`
- 图形过于复杂无法准确还原时，同样加注释说明是简化示意。

### 4. 通用格式
- 标题 `#`~`######` 严格对应原文级别，禁止跳级。
- 加粗 `**文本**`、斜体 `*文本*`；行内代码 `` `代码` ``（文件名、API 路径、`st.*` 组件、数据表名等代码标识符），代码块用 ` ``` ` 包裹并标注语言。
- 图片：`![描述](路径)` + 下方 `> 图注：xxx`。
- 脚注：`[^1]` 并在文末统一列出。
- 分页符、页眉页脚、页码：忽略不输出。

### 5. 输出要求
- 仅输出转换后的 Markdown 内容，不加解释性文字。
- 语法可直接渲染、无格式错误。
- 内容过长时分章节输出，每段标注章节标题。
- 引号曲直（"" 与 "）、原文笔误（如 `nearest_neighbor.py/`）一律原样保留，不做"修正"。

## 常见问题

- **Python 是 Windows 商店占位符**（`python` 直接退出码 49）→ 用 Node.js 方案；`python-docx`/`pandoc` 可用时也可作为交叉校验手段。
- **Node 无法读取 `/tmp` 路径** → 先 `cygpath -w` 转 Windows 路径再传参。
- **标题无 pStyle** → 按字号 + outlineLvl + 文本规律（`x.` `x.y` 编号模式）综合定级。
- **同一视觉列表多个 numId** → 以 `fmt` 判定有序/无序，按出现顺序合并为一个列表。
- **全加粗段落**（`bold=true` 且非标题）→ 作为列表项的加粗引导词（如 `- **效率价值**：…`）或加粗整段（如设计原则段）。
